# DotCov CI workflows

1. Read the affected workflow and [Fallout commands](../../../src/DotCov.Fallout/AGENTS.md).
   [nuget-publish.yml](../../../.github/workflows/nuget-publish.yml),
   [Dependabot configuration](../../../.github/dependabot.yml),
   [auto-merge](../../../.github/workflows/dependabot-auto-merge.yml), and the
   [badge action](../../../.github/actions/badge/action.yml) and its `badge.sh`
   are maintained here, not generated by Fallout. Use their current definitions
   as the source of truth for jobs, runtime packages, and permissions.
2. Trace the affected event through conditions and dependencies:

   - Pull requests run `build`, the Linux/Windows `test` matrix, and Linux `badge-action`.
   - Main pushes, version-tag pushes, and manual dispatches also run `badge-action`
     on Windows and the Linux/Windows `consumer-coverage` and `readme-badge-coverage`
     matrices. Preserve their pinned upstream revisions, native-count comparisons,
     README badge evidence, and timer checks in `.github/tests/`.
   - Only version-tag pushes and manual dispatches pack and publish release packages.
     `publish` needs build, tests, all three integration matrices, and both package
     jobs. Keep the `nuget` environment, trusted publishing, and sub-packages before
     the `DotCov.Tool` pointer. The subsequent `release` job uses
     `docs/releases/<version>.md` when `github.ref_type == 'tag'`, including a
     dispatch against a tag; a branch dispatch publishes packages only.

3. Preserve the measurement contract in the [test guide](../../../tests/AGENTS.md)
   and [build wrapper](../../../build/Build.cs): native MTP with coverlet.MTP,
   enabled by `-p:Coverage=true`, and 100% line and branch thresholds with every
   `src` project measured. Missing reports or projects cannot produce a pass.
   Locally, use `fallout Coverage` for fresh coverage or supply one concrete run
   directory with `--reports`. CI's `--reports TestResults --badge-directory badge`
   is valid because its checkout is fresh. The CI coverage gate runs only on Ubuntu;
   the Windows test leg currently cannot produce an instrumented report.
4. Keep badge publication paths distinct. Main's Ubuntu test leg draws the verdict
   in `badge/` and uploads a Pages artifact, including when the gate fails and a
   badge exists. `coverage-badge` is the only CI job with `pages: write`; it deploys
   to https://ancplua.github.io/dotcov/. Keep `contents: write` and `pages: write`
   out of `test`.
   The reusable action publishes SVG/JSON to a branch for consumers. Its CI checks
   and `BadgeActionTests` use local bare origins; the default-installer check uses
   a local-only candidate feed so a published version cannot mask this checkout.
   Preserve those origins and feeds when editing the tests.
5. Preserve event-specific concurrency: superseded PR checks may cancel, while
   main and tag runs finish. Keep the Dependabot author and same-repository guards
   around privileged auto-merge and its exclusion of major updates.
6. For workflow or badge-script changes, run `actionlint` and
   `shellcheck .github/actions/badge/badge.sh`, as the `build` job does, plus the
   smallest relevant local check through the Fallout targets. For prose-only
   skill edits, check frontmatter and links; no .NET build or test run is needed.
   Local checks do not exercise GitHub event handling; identify any unverified
   event paths. Use [dotcov-release](../dotcov-release/SKILL.md) when publication
   is also requested; an ordinary workflow edit does not authorize a release.
