# DotCov 1.5.0

CLI exit codes now distinguish failed thresholds, missing measurements, disabled gates,
and command errors. Scripts can branch on the exit code without parsing diagnostics.

| Exit | Meaning |
|---|---|
| 0 | Success; `check`, `crap`, and `test` require a measured pass |
| 1 | `FAIL:` — below a threshold |
| 2 | Unknown command |
| 3 | `NODATA:` — insufficient measurements to evaluate the gate |
| 4 | `DISABLED:` — no active threshold |
| 5 | `error:` — invalid input, parse/IO/size-cap error, upload failure, or failed test run |

## Migration

Previously, exits 3, 4, and 5 were all exit 1. Scripts that treat every nonzero result as
failure continue to work. Scripts matching exit 1 for errors or inconclusive results must
handle the new codes. Stderr verdict tokens and the library's `GateOutcome` are unchanged.

A non-passing gate retains its code if its requested upload also fails. A passing gate,
`report`, or `snapshot` returns 5 when upload fails. Reporting empty input still succeeds;
use `check` to require measurements. A failed child test run returns 5 and reports the
child's exit code without evaluating its coverage.

## Packages

`DotCov`, `DotCov.Fallout`, and `DotCov.Tool` 1.5.0, including the native osx-arm64,
linux-x64, linux-arm64 packages and the portable fallback.
