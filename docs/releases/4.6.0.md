# DotCov 4.6.0

The release workflow now waits for public runtime packages before publishing the
`DotCov.Tool` pointer. It verifies an installation from NuGet before creating the
GitHub Release.

## Installation window fixed

NuGet validates and indexes each uploaded package asynchronously. Uploading native
packages first did not guarantee they were available when the pointer appeared.
During 4.5.0 publication, the pointer could be downloaded while the two Linux native
packages returned 404.

A real isolated `dotnet tool install`, using the published pointer and portable
fallback, failed when its declared matching native package was missing. Serving
that native package made the same installation succeed. The portable fallback
protects unsupported runtime IDs; it does not rescue a missing declared package.

## Publication checks

- Keep all build, native MSTest, 100% coverage, badge-action and real-consumer gates.
- Push the six runtime/library packages, then check their public version indexes,
  registration entries and actual package downloads. Verify each package's ID,
  version and repository commit before publishing the pointer in its own job.
- Verify all seven public packages after the pointer is pushed. Install the exact
  version using only nuget.org, and compare the installed native binary with the
  downloaded native package.
- Exercise the installed CLI's version, the captured 4/6 branch report, a failing
  75% branch gate and a passing 60% gate. Create the GitHub Release only after these
  checks pass.
- Keep every availability window within four minutes. Pending windows restart in a
  fresh process, with cache-busting reads, up to five windows. Incorrect metadata
  fails immediately. Exhausted waits fail publication and retain their diagnostics.

The tests cover missing runtime packages, indexes without downloads, stale
registration leaves, delayed availability with cached responses, incorrect package
identity/version/source, corrupted archives and unusable local cache substitutes.
The verifier is also checked against the actual public 4.5.0 packages and native tool.

## Coverage and compatibility

The 4.5.0 branch ownership correction remains in place. CLI commands, JSON fields
and exit codes are unchanged. The native MSTest suite, coverage provider, measured
assemblies and 100% line/branch gates are unchanged; no exclusions are added.

```sh
dotnet tool update -g DotCov.Tool --version 4.6.0
```

Use `ANcpLua/dotcov/.github/actions/badge@v4.6.0` and `DotCov`/`DotCov.Fallout` 4.6.0.
