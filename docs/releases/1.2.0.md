# DotCov 1.2.0

This release adds `dotcov test`, closes two more ways a gate could pass without
measuring anything, and reports parser warnings once. Scripts that pass `--keep`
on its own or an infinite `--max-crap` may need a change; see
[Behavior changes](#behavior-changes).

## Packages

- `DotCov` 1.2.0, `DotCov.Tool` 1.2.0, and `DotCov.Fallout` 1.2.0.

## New

- **`dotcov test [<project>]`** runs `dotnet test` with Microsoft Code Coverage
  into a fresh `TestResults/<run>`, then reports and gates that run like `check`.
  Arguments after `--` go to `dotnet test`, for example
  `dotcov test tests/MyApp.Tests --min-line 80 -- -c Release`. A failed test run
  ends with `error:` and exit 1, and its coverage is not evaluated.

## Behavior changes

- **`--keep` requires `--exclude-generated`.** On its own it exempted nothing, so
  it now fails with `error:` and exit 1.
- **An infinite `crap --max-crap` is `DISABLED:`**, exit 1, like `check` with both
  thresholds at 0. A gate that cannot fail is not a pass.
- **The GitHub summary is written after the verdict**, so a summary-file warning
  never becomes the first stderr token.
- **`report` (table format) and `diff` print parser warnings** on stderr after the
  output. Markdown and JSON already list them.

## Other changes

- Parser warnings are recorded once per document. Coverlet repeats every line under
  its method and again in the class summary, so one malformed source line no longer
  warns several times.
