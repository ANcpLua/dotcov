# DotCov 2.0.0

The same Cobertura report can produce different numbers than in 1.x. Two parser fixes change
what DotCov counts, so thresholds and badges set on 1.x numbers can move. Commands, flags,
exit codes and the JSON shape are unchanged.

## What changes in your numbers

- **istanbul reports (Jest, Vitest): line totals now equal the tool's own.** istanbul lists each
  function's declaration line under `<methods>`, and 1.x counted those lines as file lines. A
  class's own `<lines>` now decide its file's lines; method lines count only for a class that has
  no `<lines>` of its own. Coverlet's totals do not change. On ten Vitest reports from the MCP
  TypeScript SDK, every line total now equals Vitest's; with 1.7.1, all ten were higher, by up to
  823 lines.
- **coverage.py with several `source` roots: each file keeps its own root.** 1.x prefixed every
  relative file name with the first `<source>`. A file now resolves against the root under which
  it exists on disk, so run DotCov where the sources are checked out. When the file exists under
  no root or under several, the first root applies and the report keeps the multi-root warning.
  On the MCP Python SDK's report (three roots, 414 files), 413 files now resolve to their real
  paths.
- The multi-root warning now appears only when a file stays ambiguous, not for every report
  with several roots.

## What DotCov cannot change

istanbul attaches branches only to lines that hold statements. A branch on any other line exists
only in the report's header totals, so DotCov's branch count can stay below Jest's or Vitest's
summary. The README's TypeScript section says so too.

## Upgrade

```bash
dotnet tool update -g DotCov.Tool --version 2.0.0
```

Update the badge action to `ANcpLua/dotcov/.github/actions/badge@v2.0.0` and the `DotCov` and
`DotCov.Fallout` package references to `2.0.0`.
