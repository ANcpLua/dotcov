# DotCov 3.0.1

This patch restores the complete-scoring and exclusion contracts introduced in 3.0.
Some previously green CRAP gates now correctly return `NODATA` or `FAIL`.

- **Missing executable metrics members prevent a CRAP PASS.** A method or accessor in
  the metrics file without a coverage counterpart makes the gate `NODATA` (exit `3`).
  Measured scores and offender counts remain available in the report.
  Complete overload sets match by parameter types when those identities are available,
  including dynamic/object equivalence and relational/shift operator displays.
  One metrics row cannot supply complexity to distinct methods in different files.
  Known source files and conflicting parameter signatures are respected even for a single
  candidate. Relative metrics paths use a single declared coverage source root; legacy
  hand-built metrics recover generic type identities only when the coverage scope is unambiguous.
  Unqualified custom parameter types are resolved only when unambiguous. Tuple parameters
  match their runtime `ValueTuple` forms, including names, nesting, nullable tuples, and long tuples.
  Nested-type separators and partially qualified nested names are reconciled. Nullable
  annotations on strings, objects, and arrays are erased without erasing nullable value types.
  Other nullable annotations use observed runtime type identities, including nullable generic
  references and custom nullable value types. `ref readonly` parameters preserve by-reference
  identity, and file-local compiler names reconcile with metrics while retaining source-file scope.
  Ambiguous measured overload matches retain conservative complexity scores but cannot
  silently mark an unmeasured sibling as covered. Known parameter-count mismatches are
  not accepted as coverage matches. Extension-block displays do not identify static versus
  instance members, so an inferred receiver parameter cannot establish a coverage match.
  Indexer accessors retain their parameter counts, including the setter value, so overloads
  with different numbers or types of indices can be matched independently. Nullable
  built-in value types match their runtime `System.Nullable<T>` identities. Generic type
  arity is preserved, so `Result` and `Result<T>` do not share a metrics bucket. Generic
  extension blocks retain their enclosing emitted type identity.
  Complete static/instance constructor pairs in one file reconcile their indistinguishable
  Roslyn displays while retaining the conservative maximum complexity for both.
- **Exclusions and declarations are accounted for.** Methods intentionally removed by
  file exclusions are matched for completeness without scoring them. A match must be
  unique among executable candidates: declarations without bodies do not create false
  ambiguity, while ambiguous executable overloads remain unmatched.
  Metrics source paths apply these rules even when a file is absent from coverage.
  `--keep` exemptions remain measured. Roslyn metrics with `ExecutableLines=0` do not
  require coverage or supply executable complexity. Legacy `LinesOfCode` is used only when
  `ExecutableLines` is absent; missing or invalid values do not waive
  the completeness check.
- **Async overloads keep their own bodies in either input order.** A lambda appearing
  before its async state-machine body no longer lets that body merge into a synchronous
  overload and dilute its CRAP score.
- **Merged exclusion metadata reflects the resulting files.** A file contributed by
  another report is no longer also listed as excluded. Applied rules and keep exemptions
  remain available. Retaining excluded method identities uses a set lookup to avoid
  quadratic scans on reports with many excluded files. Repeated excluded metrics identities
  are matched once instead of rescanning their candidates for every raw signature.
  Metrics candidates are summarized by parameter count, so repeated measured methods
  also avoid candidate scans and repeated string parsing. Enclosing type identities are
  cached across members, and metrics named-type nesting is bounded to 256 levels to limit
  resource amplification from deeply nested input.
  Type-name matching runs in linear time; coverage signatures and metrics member
  displays longer than 16,384 characters are rejected before signature analysis.
  Oversized XML members report the input path and member context.
  Tuple nesting is limited to 64 levels.
- **Patched Fallout dependencies.** The Fallout integration constrains its transitive
  `System.Security.Cryptography.Pkcs` and `System.Security.Cryptography.Xml` dependencies
  to 10.0.13, addressing the security advisories published on October 13, 2026.

The library adds nullable `CodeMetricsMember.ExecutableLines`, `File`, and `TypeIdentity`; existing constructor and
analysis signatures remain available. CLI flags, exit codes, and threshold rules are
unchanged from 3.0.0.

Conversion operators that differ only by return type remain `NODATA` when Cobertura
omits that target identity. Repeated entries cannot prove that both conversions were measured.

## Upgrade

```bash
dotnet tool update -g DotCov.Tool --version 3.0.1
```

Update the badge action to `ANcpLua/dotcov/.github/actions/badge@v3.0.1` and the `DotCov`
and `DotCov.Fallout` package references to `3.0.1`. The explicit thresholds and file
identity requirements from the [3.0 release notes](3.0.0.md) still apply.
