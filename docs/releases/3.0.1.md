# DotCov 3.0.1

A patch for the 3.0 CRAP gate and for exclusions. Line and branch gates are unchanged. Some CRAP
gates that passed on 3.0.0 now return `NODATA` (exit 3) or `FAIL` (exit 1); in each case 3.0.0
reported a pass it could not prove.

## CRAP gate

- **Every metrics method must be measured.** A method or accessor in the `--metrics` file with no
  coverage counterpart makes the gate `NODATA`. 3.0.0 listed it and still passed.
- **Each metrics row matches exactly one method.** Overloads match by parameter types, including
  tuples, nullable value and reference types, generics, indexers, `ref readonly`, escaped
  identifiers such as `@int`, and file-local types. A row that matches several methods stays
  unmatched, so the gate says `NODATA` instead of lending one method's complexity to a sibling.
- **Declarations without a body need no coverage.** Members with `ExecutableLines=0` (interface
  and abstract members) neither block a pass nor supply complexity.
- **A complexity below 1 is not a measurement.** A metrics row with `CyclomaticComplexity` 0 or
  negative leaves its method unscored (`NODATA`); 3.0.0 scored it 0 and could pass.
- **Async overloads keep their own body.** When a lambda preceded its state machine in the
  report, 3.0.0 could fold an async overload into a covered synchronous one and pass. CRAP
  scores for such methods rise to their own values.
- **Function-pointer parameters no longer abort `crap`.** Coverlet truncates their signature;
  3.0.0 failed with `Unbalanced tuple type`. Such methods now match by name and parameter count.
- **Excluded files stay accounted for.** Methods removed by `--exclude-*` count as measured
  without being scored, and an excluded overload never hides a kept sibling.
- Conversion operators that differ only in their return type stay `NODATA`: Cobertura omits the
  return type, so their coverage cannot be told apart.

## Reports

- A merged report no longer lists a file as excluded when another input brings it back.
- Large reports with many excluded files or large metrics files no longer scan quadratically.
  Coverage signatures and metrics names longer than 16,384 characters are rejected as input
  errors (exit 5); tuple nesting is limited to 64 levels and metrics type nesting to 256.

## Packages

- `DotCov.Fallout` requires `System.Security.Cryptography.Pkcs` and `System.Security.Cryptography.Xml`
  10.0.13, which address the advisories of October 13, 2026.
- `CodeMetricsMember` gains nullable `ExecutableLines`, `File` and `TypeIdentity`. CLI flags, exit
  codes and threshold rules are unchanged from 3.0.0.

## Upgrade

```bash
dotnet tool update -g DotCov.Tool --version 3.0.1
```

Use `ANcpLua/dotcov/.github/actions/badge@v3.0.1` and `DotCov`/`DotCov.Fallout` 3.0.1. The 3.0
threshold and file-identity rules in the [3.0.0 notes](3.0.0.md) still apply.
