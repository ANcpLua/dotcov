# DotCov 1.1.0

This release makes the CLI fail closed on input it used to ignore and makes its
diagnostics visible. Scripts written against 1.0.0 may need a change; see
[Behavior changes](#behavior-changes).

## Packages

- `DotCov` 1.1.0, `DotCov.Tool` 1.1.0, and `DotCov.Fallout` 1.1.0.

## Behavior changes

- **Unused arguments are errors.** A flag the command does not use, a misspelled
  flag, `--name=value`, or a second path now fails with `error:` and exit 1. In
  1.0.0 they were ignored, so `check --min-lin 90` gated at the default 80 and a
  shell glob gated only its first file. Write `--min-line 90`, and pass the
  directory that holds several reports instead of the files.
- **`crap` defaults to `--max-crap 30`**, the original CRAP threshold. The old
  default of 6 failed every method above complexity 6 however well it was
  tested; pass `--max-crap 6` to keep that gate.
- **stderr leads with the outcome.** A missing path, an invalid flag value, and a
  failed upload now start with `error:`, like the other could-not-run failures.
  `check` now prints parser and merge warnings, and gate commands print them
  after the verdict.

## Other changes

- When one path resolves to several reports, every command lists them on
  stderr and the Fallout component logs them, so a report an earlier run left
  in the same directory is visible.
- `snapshot` includes `fileHash` for directory input: a SHA-256 over the merged
  reports.
- A negative hit count reads as missed in line status, strict line counts, and
  `diff`, matching the line totals.
- Docs: `--exclude-generated` no longer claims to skip state machines, and DTDs
  are described as ignored (never processed) rather than prohibited.
