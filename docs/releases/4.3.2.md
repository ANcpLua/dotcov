# DotCov 4.3.2

Maintenance fixes from the repository's JetBrains inspection pass. Coverage thresholds,
exit codes, JSON contracts, and the published API remain unchanged from 4.3.1.

## Resource handling and analysis

- Reuse the upload HTTP client across CLI calls and dispose each request's JSON
  content and response after the upload completes.
- Materialize nullable method signature inputs once before deriving the matching
  sets, avoiding repeated enumeration of the source sequence.
- Initialize the test runner process inside its disposal scope.

## Documentation and maintenance

- Correct ambiguous XML documentation links, stale parameter documentation, and
  the escaped less-than character in JSON documentation.
- Simplify equivalent patterns, collection construction, private implementation
  names, constructors, and redundant test arguments.
- Make asynchronous test resource disposal explicit, propagate cancellation to
  cancellable test file operations, and keep draining child-process output after
  cancellation until the owned process has been killed and reaped.
- Retain intentional synchronous parser coverage and externally consumed public
  APIs with narrowly scoped inspection annotations explaining their contracts.

The repository-hosted coverage, CI, and release skills from 4.3.1 are included.

## Verification

- All 1,999 tests pass, with zero skipped tests.
- The repository coverage gate reports 100% of lines and branches.
- The full JetBrains inspection reports zero findings, down from 151 before cleanup.
  Narrow annotations retain intentional public APIs and synchronous test contracts.
