# DotCov 4.2.0

Names coverage that is not your code. Nothing that worked on 4.1 changes.

## Why

Coverage tools instrument every assembly that ships a PDB, so a test project's dependencies
(Testcontainers, Moq, bunit, the test platform) can end up in the report. Their files carry
SourceLink paths such as `/_/src/Docker.DotNet/...`. Codecov drops files that are not in the
repository; DotCov read the report as written. On a project at 92.6% lines that meant a 27.3%
verdict and badge with no hint why.

## New

- **`ExternalSources` warning.** A report holding files under `/_/` without declaring `/_/` as a
  source root gets one warning with the count and the first such file: on stderr, in every JSON
  document's `warnings`, and in the Fallout log. A report built deterministically itself declares
  `/_/` and gets none.
- **`--exclude-external`** on every command that reads a report removes those files like the other
  exclusions: listed on stderr and in `excluded`/`exclusionRules`. Fallout:
  `--coverage-exclude-external-param true`; library: `ExclusionRules.External`; badge action:
  `args: --exclude-external`.
- The better fix stays at the producer: measure only your assemblies, for example coverlet's
  `--coverlet-include "[YourAssembly]*"`, so every tool reads the same report.

## Upgrade

```bash
dotnet tool update -g DotCov.Tool --version 4.2.0
```

Use `ANcpLua/dotcov/.github/actions/badge@v4.2.0` and `DotCov`/`DotCov.Fallout` 4.2.0.
