# DotCov 4.7.0

`dotcov test` preserves pending Microsoft static coverage hits when a managed child
terminates with an unhandled exception. It flushes the collector's real counters
before termination; the original exception and process exit stay intact.

## Cause and correction

The Microsoft static tracker used by coverage 18.11.0 and 18.12.0 buffers hits in
private memory on Unix. It publishes periodically and on normal process exit.
Unhandled managed termination can happen between publications, losing the last
executed outcomes. A newer SDK alone does not reliably correct this timing window.

The tool embeds a small managed startup hook, extracts it into the fresh test-run
directory and appends it to `DOTNET_STARTUP_HOOKS`. On normal exit or an unhandled
exception, it finds the active collector's injected trackers in loaded assemblies,
stops and joins their periodic publication workers, then calls their public
parameterless `Flush` methods. The join is bounded to one second per tracker and
failures are reported. It preserves existing hooks and the original exception.

The hook targets .NET Standard 2.0 and is embedded in both native and portable tool
packages. It is loaded by the measured CoreCLR process. Managed startup hooks must
be enabled there; `FailFast` and OS termination cannot run this handler.

Coverage settings, measured source, reports and CLI exit codes are unchanged.
Reading an existing report does not rerun collection or manufacture missing hits.

## Verification

- A real startup failure is measured in 20 paired collector runs. With finalization,
  all 20 retain the outcome; without it, 17 lose it. Every run retains the original
  exception and exit 134.
- Complete eight-test consumer measurements retain all three assemblies and source
  files, with both outcomes at the specific startup decision.
- Native MSTest regressions cover session selection, multiple assemblies, older
  tracker shapes, flush diagnostics, idempotence and existing startup hooks.
- A permanent real MSTest/Microsoft coverage fixture checks successful and crashing
  children, the original diagnostic, an existing startup hook and raw 2/2 branches.
  CI runs it before publication and against the public native tool before creating
  the GitHub Release.
- All 2,038 native MSTest cases pass with zero skips. All four shipping assemblies,
  including the hook, meet the existing 100% line and branch gates.

## Upgrade

```sh
dotnet tool update -g DotCov.Tool --version 4.7.0
```

Use `ANcpLua/dotcov/.github/actions/badge@v4.7.0` and `DotCov`/`DotCov.Fallout` 4.7.0.
