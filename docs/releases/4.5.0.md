# DotCov 4.5.0

DotCov now preserves the IL owner of each Cobertura branch while parsing and
merging reports. Distinct methods and generated classes can share a source line
and reuse condition numbers; those numbers identify branches only within their
package, class, method name and signature.

## Correct branch totals

A real Microsoft coverage report contains a lambda with 1/2 outcomes and its
calling async state machine with 3/4 outcomes on the same source line. Previous
versions collapsed them to 3/4 (75%), allowing a 75% branch gate to pass. DotCov
4.5.0 reports all 4/6 outcomes (66.67%), and that gate fails with exit code 1.

- Add outcomes belonging to distinct owners, including methods in the same class
  and overloads sharing one source line.
- Deduplicate repeated observations of the same owner across class blocks,
  reports and shards. Class summaries remain per-line floors for their methods,
  rather than additional branch owners to count twice.
- Union condition observations only inside a matching owner. Conflicting condition
  identities still warn and retain their conservative, order-independent raw state.
- Keep source-line coverage deduplicated by file and line; fixing branch ownership
  does not turn repeated generated lines into extra source lines.

## Library and CLI contracts

`FileCoverage.BranchesByOrigin` exposes branch counts and condition maps keyed by
`BranchOrigin` (package, class, method and signature). A null method identifies a
class summary. `BranchesByLine` presents the reconciled totals. For a line with
multiple owners, integer-keyed `ConditionsByLine` cannot represent the independent
condition-number spaces; use `BranchesByOrigin` to inspect them.

Hand-built records without owner information retain their aggregate fallback.
Default structs remain empty values. CLI commands, JSON fields and exit codes are
unchanged; reports and gate outcomes reflect the corrected branch counts.

## Verification

The regression suite includes the captured Microsoft report, a real CLI failure
at 75% and pass at 60%, package/type/method/signature collisions, repeated summaries,
all merge orders, same-owner identity poisoning, and legacy aggregate behavior.
All 2,024 native MSTest cases pass locally, with zero skips. The unchanged 100%
line/branch gates cover every shipping assembly. JetBrains inspections run at
suggestion severity.

The repository keeps its existing Coverlet provider and measurement scope.

Correction after repeated collection: upgrading from Microsoft coverage 18.11.0 to
18.12.0 does not reliably retain fast unhandled child failures. The tracker can
terminate before its next periodic flush. DotCov 4.7.0 adds termination flushing to
`dotcov test`; report parsing cannot recover outcomes already missing from XML.

## Upgrade

```sh
dotnet tool update -g DotCov.Tool --version 4.5.0
```
