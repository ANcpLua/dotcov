# DotCov 1.6.0

The coverage badge now comes from the gate. `check` and `test` write it with `--badge-dir`,
the Fallout component with `--coverage-badge-directory`, and a composite action gates and
publishes it in one CI step. The colour is the gate's outcome, so a branch rate below its
minimum turns the badge red even at `100.0%` lines. DotCov's own badge used to be coloured by
the line rate alone and stayed green in that case.

| Outcome | Colour | Message |
|---|---|---|
| `PASS` | brightgreen | The line rate, and the branch rate too when the branch minimum is above 0: `100.0% / 98.5%` |
| `FAIL` | red | The same, rounded down like the verdict, never to a rate that reads as met |
| `NODATA` | lightgrey | `no data` |
| `DISABLED` | yellow | `disabled` |

## CLI

`check` and `test` take `--badge-dir <dir>` and write `coverage-badge.svg` and
`coverage-badge.json` into it, created if missing, for every outcome. When the files cannot be
written, a passing gate returns 5 with `error:`, as it does when an upload fails; a non-passing
gate keeps its code. An empty value fails before any report is read or test is run. `report`,
`crap` and `snapshot` reject the flag.

## Library

`BadgeFormatter.Svg(GateResult)` and `BadgeFormatter.ShieldsJson(GateResult)` render an
evaluated gate; `BadgeFormatter.SvgFileName` and `JsonFileName` name the files. The SVG uses
shields' flat-square geometry with Verdana 11px widths and pinned `textLength`, so the text never
clips. Its `<title>` and `aria-label` carry the full verdict, so hovering and screen readers get
the thresholds and the reason. A message character without a known width, such as a NaN rate,
throws.

## Fallout

`ICoverageReport` takes `--coverage-badge-directory <dir>`, relative to the root and empty (off)
by default. `ReportCoverage` writes both files for every outcome before the verdict can fail the
target. A pass whose badge cannot be written fails the target.

## GitHub Action

```yaml
- uses: ANcpLua/dotcov/.github/actions/badge@v1.6.0
  with:
    reports: TestResults
    min-line: 80
    publish: ${{ github.ref == 'refs/heads/main' }}
```

The action installs `DotCov.Tool` 1.6.0, runs `check … --badge-dir`, and publishes both files to
the `badges` branch. It creates that branch as an orphan on first use, commits only when the
badge's contents change, and then exits with the gate's code. `fail-on-gate: false` keeps
`FAIL`, `NODATA` and `DISABLED` green; errors still fail. Publishing needs
`permissions: contents: write`. See the [README](../../README.md#badge) for the inputs and for
private repositories.

## Packages

`DotCov`, `DotCov.Fallout`, and `DotCov.Tool` 1.6.0, including the native osx-arm64,
linux-x64, linux-arm64 packages and the portable fallback.
