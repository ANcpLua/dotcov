# DotCov 1.7.0

`dotcov --version` now prints the same version as `dotcov version`; both are supported.

## Exit-code migration

Usage errors now exit **2**, previously reserved for unknown commands: unknown or unused
flags, invalid flag values, missing required arguments, and extra positional arguments.
A missing or empty path argument is usage error 2; a supplied nonexistent or unreadable
path is execution error **5**. Malformed or non-HTTP(S) upload URLs are invalid values (2);
failed HTTP requests remain upload failures (5). Classification uses error types and
validation results, never diagnostic text. Update scripts that previously grouped usage
errors with execution failures under 5.

The other outcomes remain: **0** command success or measured gate pass, **1** threshold
failure, **3** NODATA, **4** DISABLED, **5** execution failure (including malformed reports,
report size limits, upload failures, and failed child test runs). Non-passing gates keep
their code if upload also fails; upload failure after a passing gate returns 5.

Explicit report paths, `--min-line`, `--min-branch`, and `--` for forwarded `dotnet test`
arguments are unchanged. No other aliases were added.
