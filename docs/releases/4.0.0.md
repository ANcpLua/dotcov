# DotCov 4.0.0

4.0 makes dotcov easy to drive from a coding agent or a script: one stream contract, JSON with
a gate on every gating command, and a list of exactly what to test next. Three contracts change;
coverage numbers and gate outcomes do not.

## Breaking changes

- **The verdict always goes to stderr.** Stdout carries only the command's data (table,
  markdown or JSON). The verdict line of `check`, `test` and `crap` (`PASS`, `FAIL`, `NODATA`,
  `DISABLED`) is the first stderr line in every format; 3.x printed `PASS` on stdout. `check`
  prints nothing on stdout in table format. Scripts that read `PASS:` from stdout read stderr, or
  better, the exit code.
- **A failed test run exits 6.** `dotcov test` used to exit 5 when `dotnet test` failed, the same
  code as an unreadable report. The Fallout target now exits with dotcov's own codes (1 FAIL,
  2 invalid parameter, 3 NODATA, 4 DISABLED, 5 error) instead of one generic failure.
- **JSON is reshaped.** Every document opens with `"schemaVersion": 1`, `"command"`, `"inputs"`
  (the merged reports) and `"warnings"` (always present). Per-file `uncoveredLines` arrays become
  an `"uncovered"` range string (`"14-15,21"`). `crap`'s `gate.reason` is the full verdict line,
  and its `gate` gains `exitCode`. Strings keep their characters (`<`, `'`, `ü`) instead of
  `\u` escapes, and every document ends with a newline.
- `diff` lists only the files whose coverage changed and counts the rest on one line (JSON still
  lists every file). `--no-color` is accepted by `report`, `crap`, `diff` and `test` only.
- Library: `CoverageReport.BelowPercent` is replaced by `Offenders(gate)`; `ExitCodes` holds the
  exit-code table; `DotCovCli.UnknownCommandExitCode` is gone.

## New

- **`check` and `test` speak JSON and markdown.** `--format json` prints the report plus a `gate`
  object: `outcome`, `exitCode`, `reason`, `line`/`branch` rate and minimum, and `offenders`.
- **Offenders: what to test next.** A `FAIL` lists every file below a failed threshold, branch
  thresholds included, worst first, with uncovered line ranges and partially covered branch
  lines. `--top N` caps the list (default 20) and counts the rest.
- **`report --top N`** shows the N worst files; **`crap`** shows each method's `file:line`.
- **Help from anywhere.** `dotcov <command> --help`, `-h` and `dotcov help <command>` print one
  command's usage, options, exit codes and examples.
- **Mistakes name the fix.** An unknown option suggests the closest one (`Did you mean
  '--min-line'?`) and lists the valid options; an unknown command suggests the closest command.
  Both exit 2 with nothing on stdout.
- **Empty inputs are named.** A directory that matches no report gets a warning that names the
  `.xml` files it holds and the `--pattern` that would read them.
- **`dotcov test`** prints `reports: TestResults/<run>` after the verdict, and with
  `--format json` or `md` shows the `dotnet test` log only when the run fails.
- **`--no-color`**, and `NO_COLOR` is documented; `test` passes it on to `dotnet test`.
- **Fallout:** `--coverage-json-path <file>` writes the gate document for every outcome, and
  `--coverage-format json` logs the same document `check --format json` prints.

## Upgrade

```bash
dotnet tool update -g DotCov.Tool --version 4.0.0
```

Use `ANcpLua/dotcov/.github/actions/badge@v4.0.0` and `DotCov`/`DotCov.Fallout` 4.0.0. The badge
action's inputs and outputs are unchanged.
