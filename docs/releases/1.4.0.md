# DotCov 1.4.0

This release fixes 37 bugs, each proven by a test that failed before the fix. Most of them
let a gate pass on a wrong measurement. Scripts that pass a flag without its value, or pass
a path as `--file`, `--before` or `--after`, now get an error; see
[Behavior changes](#behavior-changes). DotCov's own tests now cover 100% of its lines and
branches, and its build fails below that.

## Packages

- `DotCov` 1.4.0, `DotCov.Tool` 1.4.0, and `DotCov.Fallout` 1.4.0.

## Behavior changes

- **A flag without its value is an error.** `check cov.xml --min-line` fails with
  `error: Option '--min-line' requires a value.` and exit 1; the flag used to take the
  value `true`. The advice for `--flag=value` on a flag that takes no value now says so,
  instead of suggesting a form that fails again.
- **`--file`, `--before` and `--after` are not options.** `check failing.xml --file
  passing.xml` gated the second file and exited 0. Each now fails with
  `Unknown option '--file' for 'check'. Pass the path as a positional argument.`
- **An empty path is `error: missing path`**, exit 1, for every command. It crashed with
  exit 134 and a stack trace, which `dotcov check "$COVERAGE_DIR"` with the variable unset
  triggered.
- **`crap --max-crap Infinity --format json`** is `DISABLED:` with exit 1 like the other
  formats instead of crashing, and `crap --format json` writes valid JSON when the gate
  passes.
- **Report discovery matches file names case-insensitively on every OS.** On Linux it was
  case-sensitive, so a `Coverage.Cobertura.xml` was found on Windows and macOS only.
- **The Fallout component rejects a NaN threshold** as the CLI does, instead of failing
  against `min NaN%`. `CrapReport.Evaluate(double.NaN)` returned PASS; it fails now.
- **`fallout Snapshot` works on a detached HEAD.** The snapshot stamps the commit and the
  branch `unknown`, and says so, instead of crashing.

## Measurement fixes

Each of these gave a wrong number or verdict silently.

- A skipped `<line>`'s conditions attached to the previous branched line, so a partial
  branch read as fully covered.
- A `condition-coverage` claiming more covered than total branches was accepted, so a
  branch rate could exceed 100%.
- Merging records built from counts alone erased their counts, giving NoData or a false
  PASS.
- Hit counts beyond the integer range counted as a miss; they saturate now.
- `<source>` text split by a comment, processing instruction or CDATA lost or truncated
  the root.
- A coverage movement of exactly the movement threshold was "Unchanged" unless the
  before rate was 0.
- A method that covers line 0 reported the wrong start line.

## CRAP fixes

- Generic and non-generic overloads (`Result.Map` and `Result<T>.Map`) were merged, so an
  uncovered complex method passed the gate.
- `crap --metrics` passed a top-level program whose entry point is uncovered and risky.
- Members that never matched their metrics member, and so were never scored: explicit
  interface implementations, static constructors, destructors (read as `~T` instead of
  `Finalize`), checked operators, C# 14 compound-assignment operators, checked explicit
  conversions (which collided with the unchecked one), every member of a C# 14 extension
  block (read as a member named `extension`), tuple return types, default parameter
  values containing commas, brackets or quotes, async lambdas in constructors, and
  explicit-interface iterators.
- A positional record property scored complexity 0 and CRAP 0.0.
- An offender just above the maximum printed as exactly the maximum.

## Output fixes

- The table's TOTAL floors like the verdict: never `100.0%` directly above
  `FAIL: line 99.9% (min 100%)`.
- The markdown threshold line no longer rounds the threshold that the badge shows exactly.
- Names containing `|`, backticks or line breaks no longer break markdown tables and code
  spans.
- The markdown diff header icon honors the movement threshold.
- A measured 0% is painted as a value, not in the dim colour reserved for unmeasured
  cells.
- A NODATA gate no longer prints `files below line threshold:`.

## Other changes

- `CoberturaParser.ParseMethods` with a null input throws `ArgumentNullException` like
  `Parse`, not `NullReferenceException`.
