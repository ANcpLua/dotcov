# DotCov 3.0.0

Three gate contracts change: thresholds are explicit, the CRAP gate needs every method scored,
and file identity no longer depends on the machine reading the report. Seven fixes change what
DotCov counts. Every number a gate decides on may move, so re-check thresholds and badges set on
2.x numbers.

## What changes in your gates

- **Thresholds are explicit.** `check`, `test`, the Fallout `ReportCoverage` target and the badge
  action no longer assume `--min-line 80`. Pass `--min-line`, `--min-branch`, or both. Without
  either, `check` and `test` exit `2` before they read a report or start `dotnet test`, the
  Fallout target fails naming `Coverage MinLine` and `Coverage MinBranch`, and the badge action
  fails with dotcov's exit `2`. One threshold checks its dimension and leaves the other
  unchecked; both at `0` is `DISABLED` (exit `4`). A threshold outside 0 to 100, NaN or infinity
  is a usage error (exit `2`), and `report --threshold` follows the same range.
- **The CRAP gate needs complete scoring.** One method `crap` cannot score — no usable
  complexity, or no lines — makes the verdict `NODATA` (exit `3`); 2.x listed it and passed the
  rest. The reason names the count and the `--metrics` remedy, and the unscored and
  unmatched-metrics lists still print in every format. Emitters without a usable `complexity`
  attribute (gcovr placeholders, ReportGenerator merges, some converters) now need `--metrics` to
  pass at all.
- **File identity is deterministic.** A report with several `<source>` roots no longer makes
  DotCov look at the disk. A relative file name keeps a key under the first root, gets a
  `FileIdentityAmbiguous` warning naming its candidate roots, and `check`, `crap`, `test` and the
  Fallout target answer `NODATA` (exit `3`): "N files have ambiguous identity across M source
  roots; re-run with --probe-sources on the machine that holds the sources or supply
  --source-root". `report` prints as usual with the warning. `--probe-sources` restores 2.0's
  disk probe, whose answer depends on the machine running it; `--source-root <root>` names a
  declared root, and a root no report declares exits `2`. The Fallout target has the same modes
  as `--coverage-probe-sources-param` and `--coverage-source-root`.

## What changes in your numbers

- **Contradictory condition detail no longer lifts a line (lower branch rates).** A Coverlet
  `<condition>` set that claims more covered outcomes than its own line's `condition-coverage`
  — detail at 100% on a `(0/2)` line — used to raise the line to `(2/2)`. Such detail is now
  dropped with a `MalformedConditionCoverage` warning, and the line keeps its own aggregate. A
  `branch="true"` line without `condition-coverage`, and a condition that cannot be parsed, warn
  too instead of passing silently.
- **An empty class summary decides the file (lower line rates).** `<lines/>` and
  `<lines></lines>` now count as the class's own statement that it has no lines, as a non-empty
  summary always did: istanbul's method declaration lines no longer stand in. A file with only
  that empty summary reads `NODATA` instead of `100%`.
- **Condition identity does not depend on packaging (lower branch rates).** Two `<class>`
  blocks of one document that report the same line with different condition numbers now fall
  back to the line aggregate with a `ConditionIdentityMismatch` warning — exactly what merging
  the same blocks as two documents did. 2.x unioned them into a total no emitter reported.
- **CRAP rows stay per file (higher CRAP scores).** The same type and method in two files (two
  assemblies' `Ns.T.M(Int32)`) were one row averaging both. They are two rows now, and the
  uncovered one keeps its own score.
- **Overloads keep their own async and lambda bodies (higher CRAP scores).** All state machines
  and lambdas of a method name shared one row, so `M(int)` and `M(string)` averaged their lines.
  Synthesized code now groups by its origin's method ordinal (`<M>d__0` vs `<M>d__1`) and joins
  a named method only when that origin is proven; a method's own async body never joins a
  synchronous overload.
- **`./src/C.cs` and `src/C.cs` are one file (no double counting).** Redundant `.` segments are
  removed from file names and roots alike; `..` is kept and the disk is never read. Totals drop
  where one file was counted under two spellings.
- **The async parser finishes every class (higher line totals on `ParseAsync`).** A class whose
  lines sit only under `<methods>` contributed nothing to `CoberturaParser.ParseAsync`; it now
  gives the same report as `Parse`.

## New

`--exclude-test-code` on `report`, `check`, `crap`, `snapshot` and `test` (and
`--coverage-exclude-test-code-param` on the Fallout target) drops test projects and fixtures
(`*.Tests/`, `TestSupport/`, `TestFixtures/`) through the same predicate as
`--exclude-generated`; `--keep` exempts paths from either. Test code still counts unless you
exclude it. An active exclusion is never silent: stderr lists its rules and every excluded file
for table and markdown output, and JSON carries `excluded` and `exclusionRules`.

## Library API

`CoberturaParser.Parse`, `ParseAsync` and `ParseMethods` take a `FileIdentity`
(`Lexical`, `ProbeSources`, `FromSourceRoot(root)`); in `ParseAsync` it precedes the
cancellation token. Reports carry `AmbiguousFiles` and `Exclusion` (`FileExclusion`).
`MethodCoverageReport.Exclude` replaces `CrapAnalysis.ExcludeFiles`, and
`CrapAnalysis.Analyze(MethodCoverageReport)` carries both onto the `CrapReport`. An undeclared
explicit root throws `UndeclaredSourceRootException`. `ICoverageReport.MinLine` and `MinBranch`
are `string?` without a default.

## Upgrade

```bash
dotnet tool update -g DotCov.Tool --version 3.0.0
```

Add a threshold wherever a gate relied on the default 80. Update the badge action to
`ANcpLua/dotcov/.github/actions/badge@v3.0.0` and set `min-line`, `min-branch`, or both. Where
a coverage.py report declares several `source` roots, add `--probe-sources` on the machine that
holds the sources, or `--source-root`. Update the `DotCov` and `DotCov.Fallout` package
references to `3.0.0`.
