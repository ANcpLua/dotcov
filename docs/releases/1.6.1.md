# DotCov 1.6.1

The badge action can publish a badge your build already drew. The packages are unchanged apart
from their version.

## GitHub Action

`badge-directory` takes the place of `reports`: the action publishes the `coverage-badge.svg`
and `coverage-badge.json` that `dotcov check --badge-dir` or the Fallout component's
`--coverage-badge-directory` wrote there, without running dotcov. The gate that drew them keeps
the verdict, so its thresholds live in one place. The step fails only when the files are missing
or cannot be published. Setting both `reports` and `badge-directory`,
or neither, fails the step.

```yaml
- name: Coverage gate
  run: dotnet fallout ReportCoverage --coverage-min-line 80 --coverage-badge-directory badge
- uses: ANcpLua/dotcov/.github/actions/badge@v1.6.1
  if: ${{ !cancelled() }}
  with:
    badge-directory: badge
    publish: ${{ github.ref == 'refs/heads/main' }}
```

The action installs `DotCov.Tool` 1.6.1 when it gates itself.

## DotCov's own badge

DotCov's coverage gate now draws its badge. A `src` project missing from the coverage report
reads `no data` instead of the `PASS` the remaining projects would earn. The 100% thresholds now
live only in the build. CI also runs actionlint and shellcheck on the workflows and the action.

## Packages

`DotCov`, `DotCov.Fallout`, and `DotCov.Tool` 1.6.1, including the native osx-arm64,
linux-x64, linux-arm64 packages and the portable fallback.
