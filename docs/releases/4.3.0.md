# DotCov 4.3.0

TypeScript guidance and the scope of `crap`. Gates, numbers and output formats are unchanged.

## TypeScript

The README shows the producers that fit `dotcov check`, tried on one TypeScript project with
Vitest 5.0.4, c8 12.0.0 and Node 24:

- **Vitest** (`@vitest/coverage-v8`):
  `npx vitest run --coverage.enabled --coverage.reporter=cobertura --coverage.include='src/**'`.
  It maps V8 coverage back to the TypeScript source, so every branch counts (5 of 8 in the trial).
- **c8**, around `node --test` or any runner, no config:
  `npx c8 --all --src src --reporter=cobertura node --test`. It counts the blocks V8 ran and leaves
  out the branches of functions no test called (5 of 6 in the same trial), so its branch rate can
  read higher.
- Both report only the files a test loaded unless told where the sources are. Without
  `--coverage.include` or `--all --src`, a module no test imports is missing: the trial read
  83.3% lines instead of the true 62.5%.
- **Jest** still works with `--coverageProvider=v8 --coverageReporters=cobertura`; CI measures it
  on ts-deepmerge, and c8 on compare-versions and peek-readable.

All three write `coverage/cobertura-coverage.xml` with one `<source>` root, the working directory.

## `crap`

`crap` needs cyclomatic complexity, which only .NET emitters provide (Coverlet, or `--metrics` from
`dotnet msbuild /t:Metrics`). For a report in which no method has complexity, or which has no
method entries at all (coverage.py, Microsoft Code Coverage), the `NODATA` reason now says that
these emitters write none and points at `check`, instead of suggesting `dotnet msbuild` to a
TypeScript or Python project.

## Upgrade

```bash
dotnet tool update -g DotCov.Tool --version 4.3.0
```
